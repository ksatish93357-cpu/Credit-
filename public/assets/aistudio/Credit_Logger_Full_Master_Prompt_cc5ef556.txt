============================================================ 8.
FINANCIAL CALCULATION RULES
============================================================

Financial correctness is the highest priority.

Use exact decimal arithmetic or integer paise for money. Do not use
ordinary binary floating-point arithmetic for financial totals. Round
only for display and at explicitly defined settlement points.

Default calculation: SIMPLE INTEREST.

Support: - Monthly simple interest. - Yearly simple interest. - Optional
compound interest only if fully implemented and clearly separated.

For a monthly rate R%: One full calendar month’s interest = Principal ×
R / 100.

For a yearly rate R%: One full year interest = Principal × R / 100.

For partial periods, prorate using the actual number of days in the
relevant calendar month (monthly rate) or relevant calendar year (yearly
rate), and document the convention.

Calendar duration: - Do not assume every month has 30 days. - Respect
actual calendar month boundaries. - Support 28/29-day February, 30-day
and 31-day months, leap years and month-end dates. - Use a deterministic
month-anniversary rule. If the start day does not exist in a later
month, use that month’s final day for the anniversary; explain this rule
in the app’s calculation details. - Treat date-only values as calendar
dates, not UTC timestamps that can shift a day. - Reject a calculation
date earlier than its effective start date.

Example required by the product owner: Principal ₹1,000, monthly rate
approximately 8.3333%, start 13/01/2026, calculation date 13/07/2026.
Expected interest is approximately ₹500 and Misradhan approximately
₹1,500 (small differences may occur if the rate is entered with fewer
decimal places).

Show a calculation breakdown: - Start date. - Calculation date. -
Completed calendar months. - Remaining days. - Total elapsed days. -
Rate and rate period. - Principal basis. - Interest. - Total Misradhan.

Create one centralized calculation engine used by every screen. Do not
implement different formulas in dashboard, profile and credit details.

============================================================ 11. PAYMENT
ALLOCATION MODES
============================================================

Provide two clearly named modes. Let the user choose before saving each
payment. Also allow a default mode in settings.

MODE A: INTEREST FIRST - Apply payment to accrued interest first. -
Apply any remaining amount to principal. - Track any remaining interest
and principal separately. - Future interest accrues on the remaining
principal only. - Do not capitalize unpaid interest unless the user
explicitly selects a separate, clearly disclosed capitalization action.

MODE B: PRINCIPAL ADJUSTMENT / MISRADHAN LESS PAYMENT This is the user’s
specifically requested method.

Example: Old principal = ₹1,000. Accrued interest = ₹500. Old Misradhan
= ₹1,500. Payment = ₹1,000. New principal = ₹1,500 - ₹1,000 = ₹500.

In this mode: - Calculate interest up to the payment date. - Old
Misradhan = old principal + accrued interest. - New principal = old
Misradhan - payment. - New interest-bearing principal becomes ₹500. -
Start the next interest period from the payment date using ₹500. - Do
not continue charging interest on the old ₹1,000 principal after the
payment date.

This mode explicitly capitalizes the unpaid interest into the new
principal balance. Show this clearly in the payment preview and
statement so the calculation is transparent.

If payment equals Misradhan: - New principal = zero. - Mark the credit
settled/closed after confirmation.

If payment exceeds Misradhan: - Set credit principal to zero. - Record
the excess separately as an advance/overpayment balance. - Never create
a negative principal.

For every payment preserve: - Old principal. - Interest accrued to
payment date. - Old Misradhan. - Payment amount. - Payment date. -
Allocation mode. - New principal. - New effective interest start date. -
Advance amount, if any.
